# Module: Hooks

## Purpose

Hooks owns generation of the repository's git pre-commit and pre-push hooks and the neutral
detection of proposed gates.

It makes `persist doctor` cheap at commit time and the real test suite enforceable at push time,
without encoding a toolchain into core.

## Owns

- The tracked hook paths (`.persist/hooks/pre-commit`, `.persist/hooks/pre-push`).
- Rendering of the deterministic `sh` hook content.
- Neutral detection of the one-shot test command (`testCommand`) and proposed `prePushGates` from a
  target repository's toolchain.
- The activation command text proposed to the user.

## Does Not Own

- The `preCommitGates` / `prePushGates` / `testCommand` config field definitions (owned by
  `config`).
- Writing files or setting the executable bit (owned by `filesystem`).
- Running `git config` or any git mutation.
- Doctor checks.
- Network, telemetry, MCP runtime, AI API, or cloud behavior.

## Public Interfaces

- `detectPreCommitGates`
- `detectTestCommand`
- `detectPrePushGates`
- `isWatchCommand`
- `renderPreCommitHook`
- `renderPrePushHook`
- `PRE_COMMIT_HOOK_PATH`
- `PRE_PUSH_HOOK_PATH`
- `HOOKS_DIR`
- `HOOKS_PATH_ACTIVATION_COMMAND`

## Boundaries

Hooks produces content and proposed values. It does not write files, change git configuration, or
execute repository content. Detection only reads `package.json` and lockfiles.

## Current Decision

Governed by ADR-0014 and ADR-0009. Pre-commit runs `persist doctor` plus `preCommitGates`; pre-push
runs `persist test-gate` plus `prePushGates` and never doctor. Both hooks are generated by default
during `persist init` while staying non-destructive. Activation
(`git config core.hooksPath .persist/hooks`) runs when the user agrees (the default), never over
another tool's `core.hooksPath`; the `hooks-active` doctor check flags clones where it is off.
