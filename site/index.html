02 Check what can be checked

Catch stale context
before the next commit.

Doctor checks files and Git metadata. Missing source paths, references to unaccepted decisions, empty templates: each finding points to something you can fix.

It doesn't ask a model whether your architecture is good. That judgment stays with the people and agents doing the work.

Not evaluated

No input or no Git history? The check says why it couldn't run. It doesn't count the missing check as a pass.

Warnings advise; errors block. The generated pre-commit hook prints warnings and proceeds, failing only on errors — so unfilled templates never hold a commit hostage.

Before you start

A few useful
boundaries.

Persist OS writes and checks engineering memory. Your team still makes the decisions.

ADR-0010 · Shipped

Remember why that odd-looking code exists.

Chesterton's Fence captures smaller constraints that never became an ADR, in docs/60-engineering/FENCES.md. The fifth init question enables it; a pre-commit check warns when a change crosses a fence with no record.

Read the decision
Does it decide the architecture for me?

No. It creates the structure for your decisions and checks things with definite answers. Doctor doesn't judge whether the reasoning is good or prove that an agent has understood it.

You review the content. An agent handles the semantic review; the gate checks the artifacts.

Can I use it in an existing repository?

Yes. Run persist adopt for an adoption report and proposed ADRs, then persist init if repository memory is not set up. Review each proposal before accepting it.

Some raw-text ecosystems can over-detect development-only packages. The results stay proposed so you can reject those signals. There is no doctor baseline yet; existing findings aren't automatically treated as accepted debt.

Will init overwrite my files?

Not by default. Use --dry-run to inspect the write plan. Reinitializing an existing installation requires --force --reinit.

Init is interactive by default. --yes takes the defaults; non-interactive stdin does the same and reports it.

Do I need a hosted service or an API key?

No. Persist OS runs locally with Node.js 20 or newer. The CLI makes no network or model calls and sends no telemetry. Its two runtime dependencies are commander and zod.

Package installation may need a network connection. The no-network boundary applies to Persist OS itself, not to a test command that you configure.

What's still outside the shipped product?

Template upgrades, a doctor baseline, standalone tasks and tracker links, branch-policy configuration, and organization-wide memory are not built. This page doesn't treat them as available features.
