Persist OS
Docs npm

Git tracks what changed.
Persist OS tracks why it changed.

A local-first CLI that writes the decisions behind your code into plain files in the repository, then checks them with a deterministic doctor. Agents read the files every session. Humans review them in pull requests. No network calls, no telemetry, no model calls.

$ npx persist-os@latest init
Get started → Star on GitHub
  • MIT licensed
  • Node.js 20 or newer
  • Two runtime dependencies
The problem

The reasoning stays in the chat.

An AI tool gets a codebase to a working shape quickly. The decisions behind it, which option was picked, what was ruled out, what must not change, mostly stay in the conversation that produced them. The next session starts without them. So does the next teammate.

Persist OS puts that reasoning in the repository as Markdown, next to the code it explains, where it is versioned, reviewed, and read back. It is a small discipline system, not a memory model: the tool writes templates, you accept decisions, a check keeps them honest.

What the repository should be able to answer

  • 01What are we building?
  • 02Why did we decide this?
  • 03What must not drift?
  • 04What evidence proves this work is complete?
How it works

Six files, loaded on every session, checked before every commit.

  1. 01 · Record

    One command writes the memory

    persist init writes six documents and a decision directory: product intent, security model, quality gates, engineering standards, conventions, lessons. Each is a short template with prompts, not a guess about your stack. Feature and module memory is opt-in, and a decision is one command away.

    • docs/00-product/PRODUCT.md
    • docs/20-security/SECURITY_MODEL.md
    • docs/50-quality/QUALITY_GATES.md
    • docs/60-engineering/ENGINEERING_STANDARDS.md
    • docs/60-engineering/CONVENTIONS.md
    • docs/60-engineering/LESSONS.md
    • docs/adrs/
  2. 02 · Load

    Each AI tool gets its native entry point

    Claude Code loads CLAUDE.md, which imports AGENTS.md, and a SessionStart hook injects the list of accepted ADRs and modules. Cursor gets an always-apply rule. Codex reads AGENTS.md. Twelve agent skills ship in both the Claude and the portable Agent Skills layout.

    • CLAUDE.md, AGENTS.md
    • .claude/hooks/session-start.sh
    • .cursor/rules/persist-memory.mdc
    • .claude/skills/*/SKILL.md
    • .agents/skills/*/SKILL.md
  3. 03 · Check

    Doctor returns an exit code

    persist doctor reads the memory and exits 0, 1, or 2. The generated pre-commit hook runs it. The pre-push hook runs persist test-gate, your one-shot test command. A generated GitHub Actions workflow runs doctor on every pull request. Same input, same answer.

    • .persist/hooks/pre-commit
    • .persist/hooks/pre-push
    • .github/workflows/persist.yml
    • .persist/config.json
Decisions

A decision has a status, and the status is in the file.

persist adr create writes a Proposed ADR with Context, Decision, Alternatives Considered, and Consequences. persist adr accept promotes it to Accepted; from then on other memory can cite it as source of truth.

When the decision changes, persist adr supersede writes a new accepted ADR that links back and marks the old one superseded. Nothing is deleted or edited in place, so the trail stays readable. Doctor then warns about any memory still citing the old decision.

Proposals from persist adopt and persist mcp add land in docs/adrs/proposed/. Only a human moves them to accepted. 

$ persist adr supersede use-postgresql-for-primary-storage "Use SQLite for primary storage"

docs/adrs/ADR-0001-use-postgresql-for-primary-storage.md

-Accepted
+Accepted — superseded by ADR-0002-use-sqlite-for-primary-storage

+## Status

The gate

Doctor is deterministic on purpose.

It does not call a model and it does not judge whether your architecture is good. It checks things with a definite answer: is a required file missing, does memory cite a decision that was never accepted, has the always-loaded context outgrown its budget. Same input, same exit code, offline.

When a check has nothing to look at, it says so instead of passing. A partial run never looks like a full pass.

  • 0 Healthy No errors and no warnings.
  • 1 Warnings only Something to look at. Nothing blocks.
  • 2 Errors Memory is broken or a claim has no evidence.
  • Missing or invalid .persist/config.json, or a required document error
  • A feature folder without its plan or tasks, a module folder missing a doc, an ADR missing a section error
  • A required document links to a doc path that does not exist error
  • An ADR whose Consequences or Alternatives section says nothing (error once accepted) error / warning
  • A security-sensitive decision with no security document linked warning
  • Memory cites an ADR that does not exist, or one not yet accepted error / warning
  • Memory still cites a decision that has been superseded warning
  • Memory cites a src/ or tests/ path that no longer exists warning
  • Memory cites code that changed more than 90 days after the memory did (git only) warning
  • CLAUDE.md, AGENTS.md, and the Cursor rule together exceed 24 KiB warning
  • The product file, security model, or a module doc still holding the template prompts warning
  • CONVENTIONS.md still a stub once the repository has real work warning
  • A generated git hook that disagrees with .persist/config.json warning
  • A skill on disk that is not in the built-in catalog, retired or hand-made warning

persist doctor --json emits the same report as persist.doctor.v1 JSON, including which checks could not run and why. Every check, documented.

Agents

Memory the agent reads without being asked.

Writing the files only helps if the tool loads them. persist init wires each tool with its own mechanism, and what loads is a map, not a dump: a short index of accepted decisions and modules, with the detail one file away.

Claude Code
CLAUDE.md is loaded automatically and imports AGENTS.md. A read-only SessionStart hook in .claude/hooks/session-start.sh injects the list of accepted ADRs and modules at the start of every session.
Cursor
.cursor/rules/persist-memory.mdc is an always-apply rule, so the memory rules go into every request.
Codex and others
AGENTS.md is always written and is the portable floor. It opens with the rules: read memory first, reuse what CONVENTIONS.md names, record lessons, never contradict an accepted ADR, run persist doctor before claiming done.
Skills
Twelve workflow skills, from create-prd to completion-report, written to both .claude/skills/ and .agents/skills/. They are instructions only; generated skills contain no scripts.
Commands

The whole surface.

Every command reports what it wrote, where, and what to do next. Commands that write accept --dry-run to preview and --force to overwrite; nothing overwrites by default.

Command What it does
persist init Write the six memory documents, the decision directory, twelve agent skills, pre-commit and pre-push hooks, a CI workflow, the Claude SessionStart hook, and the Cursor rule. Refuses to overwrite an existing installation without --force --reinit.
persist init --ai-tools <list> Generate files only for the tools you use: claude, codex, cursor, generic. AGENTS.md is always written.
persist init --features --modules Also create the opt-in feature and module memory indexes.
persist adopt Inspect an existing repository through its manifests and marker files, read-only, and write a proposed adoption report plus proposed ADRs for review.
persist feature create <name> Scaffold feature memory: a plan and a task list, plus a test plan when the test gate is on.
persist adr create <title> Create a Proposed architecture decision record.
persist adr accept <name> Promote a Proposed ADR to Accepted. It becomes source of truth.
persist adr supersede <old> <new-title> Record a changed decision: a new accepted ADR that links back, and the old one marked superseded.
persist module create <name> Scaffold module memory: ownership, tasks, test plan, decisions.
persist skill create <name> Generate an agent skill for Claude Code and the portable Agent Skills layout. Catalog names get the built-in content; other names get a valid skeleton.
persist skill list List the built-in skill catalog.
persist mcp add <server> Write proposed, offline memory for an MCP server plus a proposed ADR and the capture skill. Never connects to the server.
persist doctor Check memory health, evidence, and drift. Exits 0, 1, or 2. --json for a machine-readable report.
persist test-gate Run the configured one-shot test command and require it to pass. Skips, and says so, when none is configured.

Full reference with options and generated paths in the commands documentation.

Boundaries

What it does not do.

A memory layer and a gate have to be trustworthy, so the runtime is small and the limits are explicit.

And a note on when to skip it: if you are spiking an idea you will delete next week, do not run it. There is no second session to hand off to, so the memory never gets read back. Run persist init when the code is meant to last.

  • No network calls at runtime. No telemetry.
  • No AI API calls and no connections to MCP servers.
  • No generated application code. It writes memory, not your product.
  • No architecture opinions in core. It records your decisions; it never makes them.
  • Does not install dependencies into your repository.
  • Does not overwrite existing files without --force, and refuses to write outside the repository root or through a symlink.
  • Does not enable git hooks for you. It prints the command; you run it.
Install

Start in an existing repository or an empty folder.

Requires Node.js 20 or newer. Run it once with npx, or install the persist binary globally. Either way, the first command is init, and nothing it writes is hidden from review.

Getting started → persist-os on npm 
# run without installing
npx persist-os@latest init

# or install the binary
npm install -g persist-os
persist init

# enable the generated hooks, once per clone
git config core.hooksPath .persist/hooks

# check the memory any time
persist doctor
